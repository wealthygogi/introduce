# 캐릭터 취향 모음표 및 캐릭터 관련 카테고리 설계

## 목표

기존 “캐릭터 커플링” 중심의 앱 진입을 “캐릭터 관련”으로 넓히고, 사용자가 동방 캐릭터를 원하는 격자·그룹에 배치해 테마를 적용하고 이미지로 저장할 수 있는 취향 모음표를 추가한다. 기존 커플링/관계 편집기는 경로와 저장 데이터를 보존하며 결과 이미지를 다운로드할 수 있게 한다.

## 조사 요약

- 한국어 취향표 사례는 수정 가능한 이미지 틀, 자유로운 칸 수, 사용자 정의 분류를 사용한다. 예: [캐릭터 취향 모음표 / 자캐 정리표](https://mit-archive.tistory.com/8), [캐릭터 30칸 취향표](https://tokyodiver.tistory.com/341).
- 3×3 모음 사례는 이미지 항목을 검색·배치하고 공유 결과를 만드는 흐름을 보여준다. 예: [3x3 Generator](https://gqgs.github.io/3x3-generator/).
- 큰 격자 제작기는 사용자 지정 항목과 가변 격자·공유용 출력을 제공한다. 예: [Anime Bingo](https://anime-bingo.aikats.us/). 빙고 규칙이나 점수화는 이번 기능 범위에 포함하지 않는다.
- 동방의 공식 기념 사이트는 작품별 캐릭터 탐색을 제공한다: [Touhou Project 25th character page](https://touhou-x.jp/character/). 앱의 현재 캐릭터 카탈로그는 각 캐릭터당 대표 그룹 하나만 제공하므로 완전한 출연작 관계로 오해하지 않도록 한다.
- Material Design 3 참고: [Breakpoints](https://m3.material.io/foundations/layout/breakpoints), [Layout overview](https://m3.material.io/foundations/layout/layout-overview), [Adaptive design](https://m3.material.io/foundations/layout/layout-overview/adaptive-design), [Cards](https://m3.material.io/components/cards/guidelines), [Dialogs](https://m3.material.io/components/dialogs/guidelines), [Touch targets](https://m3.material.io/foundations/designing/structure).

## 정보 구조

상위 탐색에는 “자기소개표”와 “캐릭터 관련”을 둔다. `/characters`는 두 목적 카드로 이어지는 새 진입 화면이다: “캐릭터 취향 모음표”와 “커플링·관계”. 기존 `/coupling` 및 `/coupling/whiteboard`, `/coupling/keyboard`, `/coupling/pairs`, `/coupling/matrix`는 호환성을 위해 그대로 유지한다. 관계 편집 화면의 하위 내비게이션과 저장 키도 유지한다.

신규 취향 모음표의 권장 URL은 `/characters/tastes`이며 초기 진입은 하나의 3×3 그룹이다. 여러 그룹을 추가해 그룹별 제목과 행·열을 설정할 수 있다. 셀은 빈 값, 캐릭터 한 명, 캐릭터 두 명 중 하나를 담는다. 그룹·셀의 순서는 사용자가 바꾸고, 캐릭터 중복 배치는 허용한다. 캐릭터 제거 및 크기 축소 때 나머지 셀을 자동으로 당기지 않으며, 손실이 발생할 수 있는 크기 변경은 확인 없이 적용하지 않는다.

## 취향 모음표 편집 및 데이터

별도 버전 저장 키 `introduce:characters:taste-board:v1`를 사용한다. 데이터는 제목, 그룹 목록, 테마 ID, 이름 표시 설정을 포함한다. 그룹은 안정적인 ID, 제목, 행/열, 셀 배열을 가진다. 각 셀은 0–2개의 캐릭터 ID와 선택적 조합 라벨을 담는다. 데이터 로드 시 버전·필드·ID·중복 셀 값을 검증하며 기존 초안은 수정하지 않는다.

프리셋은 한 줄 3칸, 3×3, 4×4, 5×5이며 사용자 지정 행·열도 허용한다. 초기 안전 한도는 그룹당 최대 100셀, 전체 출력 최대 300셀로 하고 실제 구현·PNG 출력 부하 검증에서 조정한다. 이를 넘는 값은 저장/렌더 단계에서 잘못된 데이터를 조용히 잘라내지 않고 사용자에게 설명한다.

캐릭터 선택은 기존 검색/작품 필터 컴포넌트를 재사용한다. 앱 카탈로그의 `group`은 대표 분류일 뿐 모든 작품 출연 이력을 뜻하지 않으므로 UI는 “대표 분류” 맥락을 제공하거나, 자유 그룹에서는 캐릭터 전체 검색을 기본으로 한다. 작품별 템플릿은 사용자가 고른 작품명으로 그룹을 생성하며 그룹의 캐릭터를 자동 채우지 않는다.

## 테마 및 다운로드

모음표 테마는 데이터와 분리된 세 가지 출력 프리셋으로 시작한다: 미니멀(밝은 배경·선명한 격자), 앨범(따뜻한 종이·사진 프레임), 나이트(짙은 배경·높은 대비). 테마 변경은 제목, 그룹, 캐릭터와 셀 위치를 바꾸지 않는다. 사이트의 라이트/다크 모드와 다운로드 이미지 테마는 독립적이다.

모바일 미리보기는 전체 결과를 축소하되 출력 그리드의 행·열을 바꾸지 않는다. 칸 편집은 터치 가능한 큰 모달/다이얼로그에서 수행하며 조작 대상은 최소 48px을 목표로 한다. 데스크톱은 편집 패널과 결과 미리보기를 나란히 보여준다.

PNG는 현재 `captureCardBlob`/`saveBlob` 기반 흐름을 확장해 저장 전용 DOM을 캡처한다. 취향 모음표는 고정 출력 폭을 사용해 모바일/PC에서 동일한 결과 구도를 보장한다. 버튼, 선택 포커스, 검색 UI는 이미지에 포함하지 않는다. 다운로드는 작업 중 상태, 실패 피드백, 재시도를 제공하며 이미지 생성 실패가 편집 데이터에 영향을 주지 않는다.

기존 네 관계 편집기도 “이미지로 저장”을 제공한다. 저장 범위는 다음과 같다: 자유 캔버스는 전체 노드·관계, 키보드 릴레이는 현재 중심에 연결된 전체 관계, 커플 카드 컬렉션은 현재 필터 결과(전체/필터 결과 문맥을 버튼에서 명시), 관계 매트릭스는 현재 방향 모드 전체 표. 콘텐츠가 페이지/스크롤에 잘리지 않도록 전용 출력 영역 또는 출력 대상 크기 캡처를 사용한다. 기존 초안 스키마·키는 변경하지 않는다.

## Material 3 / 반응형 원칙

- 상위 카테고리는 두 개로 유지해 목적을 쉽게 찾게 한다. 데스크톱은 기존 상단 내비게이션 패턴을 유지하고 모바일은 가로로 넘칠 때 메뉴를 스크롤할 수 있게 한다.
- 카드는 서로 다른 작업 목적(취향표, 관계 편집기)을 구분하는 데만 사용한다. 모든 셀을 카드처럼 무겁게 장식하지 않는다.
- 폭에 따라 편집기/미리보기의 배치를 전환하되, 결과물의 레이아웃·열 수는 뷰포트에 의해 바뀌지 않는다.
- 캐릭터 검색은 초점과 키보드 접근성을 갖춘 다이얼로그/모달을 사용하고, 모바일에서는 화면에 맞는 크기와 스크롤을 보장한다.
- 반응형 전환은 breakpoint에 따른 패널 배치 변화로 처리하고 작은 화면에서 조밀도를 일괄 낮추지 않는다.
- 저장 중/성공/실패는 조작 가까이서 확인할 수 있게 한다. 색상만으로 테마나 관계를 구분하지 않는다.

## 오류 및 제한 처리

- 로컬 저장소 사용 불가 시 현재 탭에서 편집할 수 있고 경고를 표시한다.
- 잘못된/미래 버전 데이터는 덮어쓰지 않고 기본 빈 문서로 복원하되, 복원 경고를 유지한다.
- 이미지·폰트가 준비되지 않으면 캡처 전에 기다리고, 타임아웃/실패는 재시도 가능한 오류로 알린다.
- 휴대폰에서 파일 다운로드 API 동작이 제한되는 경우 다운로드 링크를 새 탭/이미지 보기로 대체할 수 있게 한다. Web Share는 지원 여부를 확인할 수 있을 때만 보조 액션으로 제시한다.
- 지나치게 큰 출력은 브라우저 메모리 위험이 있으므로 출력 픽셀 면적을 검사하고, 제한 초과 시 크기 축소 선택지를 제공한다.

## 검증 기준

- 기존 coupling 회귀 테스트가 모두 통과하고 저장 키/형식이 변경되지 않는다.
- 새 모음표는 각 프리셋, 사용자 지정 격자, 여러 그룹, 빈칸, 중복 캐릭터, 2인 셀, 교체/이동/Undo/저장 복원을 검증한다.
- 잘못된 데이터와 격자 축소 경계에서 조용한 항목 손실이 없다.
- PNG 실제 다운로드 이벤트가 데스크톱 및 모바일 에뮬레이션에서 발생하고 파일을 PNG 디코더로 검증한다. PC와 모바일에서 같은 데이터로 동일한 출력 치수와 콘텐츠를 만든다.
- 다운로드 결과에 편집 버튼·선택 상태가 없고, 마지막 행/그룹/관계가 누락되지 않는다.
- Chromium 자동화는 반드시 수행한다. WebKit/Firefox 사용 가능 시 실행하고, 실제 iOS/Android 기기 확인은 수행 여부를 명시적으로 보고한다.
- `npm run build`, `npm run test:coupling`, 관련 다운로드·프로필 회귀, `git diff --check`가 통과한다.

## 비목표

자유 좌표 캔버스, 임의 이미지 업로드, 티어 점수/랭킹, 공개 갤러리, 계정 동기화, 작품별 전 출연 캐릭터 그래프, 사용자 정의 폰트/색상 편집은 첫 버전에 포함하지 않는다.
